# SirusChatWheel: GitHub и выпуски

Это исходники аддона WoW Sirus 3.3.5a / Lua 5.1. Пользователям игры нужны
готовые ZIP из Releases. Исходный репозиторий содержит вложенную папку
`SirusChatWheel`, инструменты сборки и проверки.

## Как разместить на GitHub

1. Распакуйте архив `SirusChatWheel-1.2.4-source.zip` в отдельную папку для
   разработки, например `Documents\SirusChatWheel`. В её корне должны быть
   `.gitignore`, этот документ, `SirusChatWheel`, `tools` и `tests`.
2. В GitHub Desktop выберите File → Add local repository и эту папку.
   Если репозитория ещё нет, используйте предложенное создание репозитория
   в этой папке. Проверьте список файлов, создайте первый commit.
3. Нажмите Publish repository, назовите репозиторий `SirusChatWheel`.
   Для проверки версии без токенов репозиторий должен быть публичным:
   отключите Keep this code private перед публикацией.
4. На GitHub откройте Releases → Draft a new release. Создайте тег
   `v1.2.4`, укажите описание и прикрепите два файла:
   `SirusChatWheel-1.2.4.zip` и `SirusChatWheel-1.2.4-update.zip`.
   Опубликуйте обычный стабильный выпуск и отметьте его Latest.
   Автоматический архив Source code не заменяет установочный ZIP.

После этого URL репозитория выглядит как `https://github.com/ВАШ_ЛОГИН/SirusChatWheel`.
В этой подготовке репозиторий ещё не создан и файлы на GitHub не отправлены.

## Как проверять обновления у игрока

1. В установленном аддоне запустите `Check-Updates.cmd`.
2. В первый раз вставьте URL публичного репозитория или `ЛОГИН/SirusChatWheel`.
   Адрес сохранится в локальном `UpdateConfig.json`. Токен не нужен.
3. Скрипт проверит последний стабильный GitHub Release с тегом `vX.Y.Z`
   или `X.Y.Z`. Он покажет установленную и опубликованную версии.
4. Если игра открыта, выполните `/reload`, затем `/scw update`.
   При входе аддон сам сообщает только о более новой версии по свежей проверке.
5. `Start-ChatWheel.cmd` также проверяет версию перед запуском игры, когда
   адрес уже настроен. Ошибка проверки не прерывает запуск игры.

Стандартный Lua-код аддона не делает запрос GitHub. Запрос выполняет внешний
PowerShell, а результат загружается из `UpdateStatus.lua` при входе или
`/reload`. Результат старше суток считается устаревшим. Обычный запуск через
лаунчер Sirus сам внешний скрипт не запускает: используйте `Check-Updates.cmd`
вручную. Скрипт не скачивает и не устанавливает код; обновление выполняется
распаковкой `-update.zip` поверх установленной папки аддона.

Если GitHub недоступен, репозиторий закрыт, релиза ещё нет или исчерпан
лимит API, проверка сообщает о неудаче, а не об отсутствии новых версий.
Предварительные релизы и нестандартные теги проверкой не поддерживаются.
Адрес можно изменить в `UpdateConfig.json` либо запуском из PowerShell:

```powershell
.\Check-Updates.ps1 -Repository 'ЛОГИН/SirusChatWheel'
```

## Как выпускать следующие версии

1. Измените номер в `Core.lua` и `SirusChatWheel.toc` на один и тот же `X.Y.Z`.
2. Обновите описание и отчёт о проверках.
3. В корне исходников выполните `python tools/build_release.py` на Windows.
   Сборка использует встроенный Windows PowerShell 5.1. Python требуется
   только разработчику, игроку он не нужен.
4. Сборщик создаст в `dist` полный ZIP, ZIP обновления и исходники. В них
   не попадут локальная настройка GitHub, результаты проверок, пользовательские
   записи и SoundNames.json из рабочей установки. Для полной установки
   каталог и кэш собираются заново из двух встроенных образцов.
5. Создайте commit, опубликуйте изменения и Release с тегом `vX.Y.Z`;
   приложите полный ZIP и ZIP обновления. Сравниваются три числа версии:
   `1.10.0` корректно считается новее `1.9.9`.

`.gitignore` исключает пользовательские звуки, кроме встроенных Cat.wav и
Dog.wav, а также Catalog.lua, SoundNames.json, Media\Cache, UpdateConfig.json
и UpdateStatus.lua. Если хотите изменить стандартные названия для всех,
редактируйте `SoundNames.example.json`. Файлы WTF не входят в проект.

Исходный checkout не является готовой установкой: сгенерированные файлы
появляются при сборке. Устанавливайте полный ZIP из `dist` в Interface\AddOns.
Для воспроизведения локальных проверок установите `lupa` в Python и запустите
`python tests/validate.py`. Если сгенерированных Catalog.lua, SoundNames.json
и UpdateStatus.lua ещё нет, стенд создаст их; существующие файлы сохранит.
Проверка имитирует API WoW и не заменяет Sirus.

Документация API GitHub:
https://docs.github.com/en/rest/releases/releases#get-the-latest-release
